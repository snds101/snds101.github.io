Embedded & Automotive Pentesting

A walkthrough of the attack surface, from datasheet to CAN bus.

01 · Overview

Embedded & Automotive Penetration Testing

Mapping attack surface from silicon to the vehicle network — ECU/MCU hardware, firmware, and the diagnostic and communication protocols that connect them.

02 · Debug Interfaces

JTAG / SWD / CoreSight

  • Datasheet and TRM review to locate debug pins and access ports
  • Pinout identification and interface enumeration on unknown boards
  • Debug authentication, lock states, and secure-debug bypass feasibility
  • Trace/ETM capability assessment for runtime analysis

03 · Boot & Flash Security

Secure Boot, Flash Protection & Firmware Extraction

  • Boot chain validation and trust anchor review
  • Readout protection (RDP) level assessment
  • Firmware extraction and static/dynamic reverse engineering
  • Identifying downgrade and bypass paths in the boot flow

04 · Vehicle Networks

CAN / CAN-FD / LIN & UDS (ISO 14229)

  • Bus sniffing, DBC reverse engineering, and message injection
  • UDS diagnostic service enumeration (read/write memory, routines)
  • Security access seed-key algorithm analysis
  • Gateway and ECU segmentation testing across bus domains

05 · Crypto & HSM

HSM / CSEc / Crypto Engine Review

  • Key storage and provisioning workflow assessment
  • Crypto engine API surface and misuse analysis
  • Side-channel exposure of key material

06 · Fault Injection

Fault Injection & Side-Channel Feasibility

  • Voltage and clock glitching for boot/auth bypass
  • EM and power analysis feasibility scoping
  • Glitch window identification against target timing

07 · Methodology

How an Engagement Runs

  • Datasheet / TRM review → interface & attack-surface mapping
  • Hardware access → firmware extraction
  • Static + dynamic analysis of firmware and protocol stack
  • Findings, exploitability writeups, and remediation guidance
